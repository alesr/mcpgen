## `mcpgen check` stages

Stages run in this order; each reports `passed`, `failed`, or `skipped`. Exit 0 means no stage failed.

| # | Stage | What it does |
|---|---|---|
| 1 | `prerequisite` | the Go toolchain is on `PATH` (otherwise the pipeline stops with exit 6) |
| 2 | `config` | `mcpgen.json` loads and validates (format version 1) |
| 3 | `serverjson` | `server.json` is a valid MCP Registry descriptor (required fields, semver, OCI package block) |
| 4 | `tidy` | `go mod tidy` succeeds and `go.mod` still pins `github.com/modelcontextprotocol/go-sdk v1.8.0` |
| 5 | `fmt` | `gofmt -l .` reports no files |
| 6 | `vet` | `go vet ./...` is clean |
| 7 | `build` | `go build ./...` succeeds |
| 8 | `test` | `go test -race ./...` passes |
| 9 | `conformance` | the official `@modelcontextprotocol/conformance` suite passes its protocol-level scenarios against the built server on a loopback address (see [check and conformance](/mcpgen/concepts/check-and-conformance/)) |
| 10 | `inspector` | optional (`--inspector`) Inspector v2 CLI smoke check; a debugging aid, not a gate |

Skip rules: stages after a failed `config` are skipped (`config invalid`); `conformance` is skipped unless node/npx are present and the transport is `http` and the protocol is `compat` (an explicit `--conformance` without node/npx fails with exit 6); `inspector` runs only with `--inspector`. The `prerequisite` stage appears only when the Go toolchain is missing.
